# 変換コスト — MediaConvert の課金構造と Fargate ffmpeg の実費

## 結論

MediaConvert は「出力分数 × 正規化係数」で課金し、**HD (720〜1080) の係数は 2.0**。
1080p を 267 分出力すれば 534 分ぶん請求される。月 4〜4.5 時間の HD 変換で
**$4.7/月 ≈ $57/年**。

係数を下げる手立ては解像度を落とすことだけで、それは画質の恒久的な代償を払う。同じ
ffmpeg パイプラインを ECS Fargate で回せば **$0.1〜0.5/月** で済むので、変換は Fargate 上の
ffmpeg で行う（[architecture.md](./architecture.md)）。

## MediaConvert の実測値

ジョブ履歴 (39 件) の出力時間と Cost Explorer の請求分数は、係数 2.0 で完全に一致する。

| 月 | ジョブ数 | 1080p 出力 | 請求分数 (HD) | 比 |
|---|---|---|---|---|
| 2026-08 | 15 | 266.77 分 | 533.54 分 | **2.000** |
| 2026-09 | 6 | 125.17 分 | 250.34 分 | **2.000** |

SD 出力 (640x360、480x852) は 1:1 で請求されており、係数 1.0。

- 39 ジョブすべて `COMPLETE`、videoId の重複ゼロ。二重変換による無駄はない。
- 単価は ap-northeast-1 Basic tier で **$0.0085 / 正規化分**。
- 8 月実績: HD $4.535 + SD $0.181 = **$4.72/月 ≈ $57/年**。

## 正規化係数表 (Basic tier / AVC, ap-northeast-1)

Price List API の `normalization_ratio` 属性より。

| 解像度 | ≤30 fps | 30–60 fps | 60–120 fps |
|---|---|---|---|
| SD (<720) | 1.0 | 1.247 | 1.494 |
| **HD (≥720, ≤1080)** | **2.0** | 2.494 | 3.0 |
| 4K (>1080, ≤2160) | 4.0 | 5.0 | 6.0 |

- **`Single pass` と `Single pass HQ` の係数は完全に同一。** `QualityTuningLevel` や
  `RateControlMode` (QVBR) をいじっても 1 円も変わらない。リザーブドキューも時間課金なので
  この規模では桁が上がる。**効くのは解像度だけ。**
- 解像度の判定は**横長なら縦、縦長なら横**の画素数。縦長 1080x1920 は「横 1080」で HD 判定。
- fps の影響は小さい (HD で 30→60fps は +25% のみ)。
- 出力あたりの最低課金は 10 秒。サムネイル (1 秒) は 39 本で年 $0.03 程度、無視してよい。

## 解像度で削るのが MediaConvert では詰む理由

出力を SD に固定すれば係数 2.0 → 1.0 で 50% 削減 ($2.3/月) になるが、動画ライブラリが
恒久的に 480p になる。$28/年 のために払う代償として重い。

上限としてキャップする形も安全には書けない。**`VideoDescription` の Width/Height は上限では
なく絶対指定**で、どの `ScalingBehavior` でも副作用が出る。

- `DEFAULT` (fit with padding): 出力枠は必ず 1920x1080。縦動画 1080x1920 が
  レターボックスされて横枠に収まる。実データに縦動画があり (1080x1920, 720x1268,
  480x852, 480x1036) 実害が出る。
- `FIT`: パディングはしないが、**入力が小さければ拡大する** (公式例: 200x200 →
  300x300)。640x360 の SD ソースが 1920x1080 に引き伸ばされ、係数 1.0 → 2.0 で
  **逆に値上がりする**。
- `Height: 1080` のみ: アスペクト比は保たれるが縦基準なので、縦動画 1080x1920 が
  608x1080 に縮む。

正しくやるには投入前にソースの向きと解像度を probe して Width/Height を出し分ける必要が
ある。ffmpeg なら `-vf scale='min(1920,iw)':-2` の一行で片付く。

## Fargate ffmpeg の実費

Fargate オンデマンド 4vCPU/8GB、ap-northeast-1 = $0.2465/時。

| ケース | 所要時間 | 月額 |
|---|---|---|
| 全部を再エンコード (2.5 倍速と仮定) | 1.76 時間 | **$0.43** |
| ほぼ remux | 0.09 時間 | **$0.02** |

ECR (~$0.05) と Public IPv4 (~$0.01) を足しても **$0.1〜0.5/月**。

`buildHlsCodecArgs` は H.264/AAC ソースを `-c:v copy` でストリームコピーするので、ソースが
H.264 なら再エンコードすら発生せず remux のみ (実時間の数十倍速) で終わる。アップロード済み
ソースは変換後に削除されるため実際の分布は追えないが、どちらに転んでも MediaConvert の
$4.54 に対して 90% 以上安い。

## 前提 — 有料のネットワークリソースを置かない

変換料金が月 $0.5 の水準なので、月額のかかるネットワークリソースを 1 つ足すだけで削減が消える。

- NAT Gateway: **$0.062/時 ≈ $45/月** — MediaConvert の請求の 10 倍
- Interface VPC エンドポイント (ECR/S3/DynamoDB/Logs の 4 つ): **~$40/月**

変換タスクの VPC は `natGateways: 0` の public subnet だけで構成し、タスクは
`assignPublicIp: ENABLED` で直接外に出る。S3 だけは無料の Gateway エンドポイントを通す
(`infra/lib/videoplayer-stack.ts`)。
